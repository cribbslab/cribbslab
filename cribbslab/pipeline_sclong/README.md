# Single-cell long-read RNA-seq pipeline (`pipeline_sclong`)

Analysis of 10x Genomics single-cell long-read RNA-seq from Oxford Nanopore
(ONT) nuclei libraries. The workflow assigns cell barcodes with BLAZE,
aligns with minimap2, discovers and quantifies isoforms with IsoQuant,
builds spliced/unspliced count matrices, and produces MultiQC plus an IsoQuant
HTML report. FLAMES (smaller samples), fusion calling (ctat-LR-fusion), and
per-cell SNV calling (longshot) are optional add-ons.

## Quick start

```bash
# 1. Create the conda environment (see below)
mamba env create -f conda/environments/sclong.yml
conda activate sclong
pip install multiqc

# 2. Install cribbslab in the same environment
pip install -e .

# 3. Set up a project directory with FASTQs and reference files
mkdir my_sclong_run && cd my_sclong_run
# ... place inputs (see "Inputs you provide") ...

# 4. Generate and edit pipeline.yml
cribbslab sclong config
# edit genome_fasta, GTF paths, tenx_kit, etc.

# 5. Run
cribbslab sclong make full --local -j 8
```

Run from the **project directory** that contains your FASTQ files and
`pipeline.yml`. Ruffus discovers samples from `*.fastq.gz` (or `.fastq`,
`.fq`) in the current directory.

## Environment

Use the dedicated `sclong` conda environment:

```bash
mamba env create -f conda/environments/sclong.yml
conda activate sclong
pip install multiqc   # not in the yml; avoids conda solve issues
pip install -e .      # from the cribbslab repo root
```

**Apple Silicon:** several Bioconductor packages (FLAMES, etc.) are only
available for `osx-64`. Create the environment under Rosetta:

```bash
CONDA_SUBDIR=osx-64 mamba env create -f conda/environments/sclong.yml
conda activate sclong
conda config --env --set subdir osx-64
```

**Optional — fusion calling:** ctat-LR-fusion runs inside a Singularity/Docker
container configured in `pipeline.yml` (`fusion.run_prefix`). The conda env
does not include the CTAT binary itself.

## Inputs you provide

These files must exist **before** running the pipeline. Everything else
(BAMs, count matrices, QC reports) is generated by the workflow.

### 1. Raw sequencing reads

One FASTQ file per sample in the project root. The basename becomes the sample
ID (e.g. `PBMC1.fastq.gz` → sample `PBMC1`).

Supported extensions: `.fastq.gz`, `.fastq`, `.fq.gz`, `.fq`

```
my_sclong_run/
├── PBMC1.fastq.gz
├── PBMC2.fastq.gz
├── pipeline.yml
└── ...
```

Reads should be from a 10x Chromium single-cell long-read library sequenced
on ONT, with the correct chemistry (`3v3`, `5v2`, etc.) set in
`pipeline.yml`.

### 2. Reference genome (FASTA)

A single reference FASTA, indexed by minimap2 during the run. Use the same
assembly as your annotation (typically GRCh38).

Example sources:

- [GENCODE human releases](https://www.gencodegenes.org/human/) — download
  `GRCh38.primary_assembly.genome.fa.gz` (or the `.p14` patch release if
  that matches your annotation).
- [10x Genomics reference bundles](https://www.10xgenomics.com/support/software/cell-ranger/downloads)
  — GRCh38 FASTA if you want parity with Cell Ranger references.

Set in `pipeline.yml`:

```yaml
genome_fasta: /path/to/GRCh38.primary_assembly.genome.fa
```

The same path is reused under `flames.fasta` and should match all GTF fields.

### 3. Gene annotation (GTF)

GTF used for splice junctions (minimap2), FLAMES, IsoQuant, featureCounts, and
velocity. Must be consistent with `genome_fasta`.

Example: [GENCODE v46 annotation](https://ftp.ebi.ac.uk/pub/databases/gencode/Gencode_human/release_46/gencode.v46.annotation.gtf.gz)

Set the same file in each GTF field (or rely on defaults once the first is
set):

```yaml
minimap2:
  gtf: /path/to/gencode.v46.annotation.gtf.gz
flames:
  gtf: /path/to/gencode.v46.annotation.gtf.gz
featurecounts:
  gtf: /path/to/gencode.v46.annotation.gtf.gz
velocity:
  gtf: /path/to/gencode.v46.annotation.gtf.gz
isoquant:
  gtf: /path/to/gencode.v46.annotation.gtf.gz
```

### 4. 10x kit and BLAZE settings

Set the library chemistry — this controls barcode/UMI positions and the
built-in 10x whitelist BLAZE uses:

```yaml
tenx_kit: 3v3          # or 3v2, 5v2, 5v3
blaze:
  kit: 3v3
  expect_cells: 5000   # rough expected cell count
```

You do **not** need to download a separate 10x whitelist for standard
chemistries; BLAZE selects the official list from the kit version. Only set
`blaze.whitelist` for custom/non-standard barcodes.

### 5. Optional — fusion calling (ctat-LR-fusion)

Only required if you run `make fusions`.

| Resource | Purpose | Where to get it |
|----------|---------|-----------------|
| CTAT genome lib | Reference plugin for ctat-LR-fusion | [CTAT_RESOURCE_LIB](https://data.broadinstitute.org/Trinity/CTAT_RESOURCE_LIB/) — e.g. `GRCh38_gencode_v44_CTAT_lib_Oct292023.plug-n-play.tar.gz` (~36 GB). **Must match** your reference/GTF; if you use Gencode v46 you may need to build a custom lib with [ctat-genome-lib-builder](https://github.com/NCIP/ctat-genome-lib-builder). |
| Container image | Runs ctat-LR-fusion | [CTAT Singularity builds](https://data.broadinstitute.org/Trinity/CTAT_SINGULARITY/ctat-LR-fusion/) — e.g. `ctat_lr_fusion.v1.1.1.simg`, or Docker `trinityctat/ctat_lr_fusion` |

```yaml
fusion:
  call_fusions: true
  ctat_resource_dir: /path/to/ctat_genome_lib
  run_prefix: singularity exec --bind $PWD /path/to/ctat_lr_fusion.sif
```

## Configuration

Generate a default `pipeline.yml` in your project directory:

```bash
cd my_sclong_run
cribbslab sclong config
```

Edit the copied file (or edit the template at
`cribbslab/pipeline_sclong/pipeline.yml` before copying). At minimum, update:

- `genome_fasta`
- All `gtf` paths (`minimap2`, `flames`, `featurecounts`, `velocity`, `isoquant`)
- `tenx_kit` / `blaze.kit`
- Thread and memory settings for your machine or cluster

For HPC, uncomment and adjust the `cluster:` block at the bottom of
`pipeline.yml`.

## Running the pipeline

All commands are run from the project directory (where FASTQs and
`pipeline.yml` live).

### Via cribbslab CLI (recommended)

```bash
cribbslab sclong make full --local -j 8
```

### Directly

```bash
python /path/to/cribbslab/cribbslab/pipeline_sclong.py make full --local -j 8
```

Common options:

| Flag | Meaning |
|------|---------|
| `--local` | Run jobs on the local machine (omit on clusters using DRMAA) |
| `-j N` | Parallel jobs |
| `-v 5` | Verbose logging |
| `--force` | Rerun tasks even if outputs exist |

### Targets

| Target | What it runs |
|--------|----------------|
| `full` | End-to-end: BLAZE → align → tag → IsoQuant → splice matrices → MultiQC → IsoQuant HTML report |
| `align` | BLAZE, minimap2 alignment, BAM tagging only |
| `quantify` | IsoQuant + featureCounts + splice matrices (needs alignment upstream) |
| `flames` | Opt-in FLAMES from FASTQ (set `flames.run: true`; prefer for smaller samples) |
| `velocity` | Opt-in legacy R velocity counting (set `velocity.run: true`; prefer IsoQuant matrices) |
| `qc` | NanoPlot, barcode summary, MultiQC, IsoQuant HTML report |
| `isoquant_report` | Regenerate IsoQuant static HTML only |
| `fusions` | ctat-LR-fusion + per-read/per-fusion tables (opt-in; set `fusion.call_fusions: true`) |
| `targeted_fusions` | Whitelist translocation window scan per cell (opt-in; set `targeted_fusion.run: true`) |
| `variants` | Per-cell longshot SNV calling + genotype matrix (opt-in; set `snv.call_variants: true`) |

Typical partial reruns:

```bash
# Re-align after changing minimap2 options
cribbslab sclong make align --local -j 8

# Re-quantify without realigning
cribbslab sclong make quantify --local -j 8

# QC and reports only
cribbslab sclong make qc --local -j 4
```

### Optional add-ons

**FLAMES** (smaller samples only; not in `full`):

IsoQuant is the default discovery route and scales better to high cell counts.
FLAMES can exceed ~40G RSS and OOM on large nuclei libraries. For smaller
samples, enable and run separately:

```yaml
flames:
  run: true
  threads: 4
  memory: 64G
```

```bash
cribbslab sclong make flames --local -j 2
```

Outputs under `flames/{sample}/`.

**Fusions** (after a successful `align` or `full` run):

```yaml
# pipeline.yml
fusion:
  call_fusions: true
  ctat_resource_dir: /path/to/ctat_genome_lib
  run_prefix: singularity exec --bind $PWD /path/to/ctat_lr_fusion.sif
```

```bash
cribbslab sclong make fusions --local -j 4
```

Outputs under `fusions/{sample}/`.

**Targeted translocation scanning** (after `align` or `full`; complements ctat-LR-fusion):

Scans the barcode-tagged BAM for reads whose alignments land in both windows of
known translocation pairs (e.g. myeloma t4;14 IGH–NSD2). Aggregates supporting
reads and UMIs **per cell barcode** and writes a cell × translocation matrix.

```yaml
targeted_fusion:
  run: true
  whitelist: /path/to/cribbslab/cribbslab/pipeline_sclong/fusion_whitelist.tsv
  bam_source: cells          # cells (tagged_cells) | all (tagged)
  window_size: 1000000
  padding_units: windows     # windows | bp
  min_mapq: 20
  matrix_window: exact       # exact | broad
```

Whitelist TSV columns (required: `cluster`, `chr_left`, `chr_right`):

| Mode | Columns | Example |
|------|---------|---------|
| Bin-based | `bin_left`, `bin_right` | t4;14 chr4 bin 2 + chr14 bin 106 (1 Mb windows) |
| Midpoint-based | `mid_left_bp`, `mid_right_bp` | centre each window on a breakpoint coordinate |
| Optional per row | `window_size`, `pad_left`, `pad_right` | override defaults; padding in windows or bp |

```bash
cribbslab sclong make targeted_fusions --local -j 4
```

Outputs under `targeted_fusions/` per sample:

- `{sample}.targeted_fusion.per_target.tsv` — sample-level summary (bulk-equivalent + `n_cells`, `n_umis`)
- `{sample}.targeted_fusion.per_cell.tsv` — long table: barcode × translocation support
- `{sample}.targeted_fusion.matrix.umi.tsv` — wide cell × translocation UMI matrix
- `{sample}.targeted_fusion.matrix.reads.tsv` — wide cell × translocation read matrix
- `{sample}.targeted_fusion.per_read.tsv` — per-read evidence with CB/UB tags

**Per-cell SNVs** (computationally heavy):

```yaml
snv:
  call_variants: true
```

```bash
cribbslab sclong make variants --local -j 8
```

Outputs under `snv/{sample}/`. wf-single-cell reports ~24 h on 64 cores for
~1500 cells; scale thread counts in `pipeline.yml` accordingly.

## IsoQuant settings

Default IsoQuant invocation (from `pipeline.yml`):

```yaml
isoquant:
  binary: isoquant
  mode: tenX_v3
  threads: 4
  umi_threads: 1          # lower peak RAM during UMI dedup
  process_threads: 1
  analysis: quantification   # reference quant only; no model construction
  large_output: none         # minimal intermediates; use read_assignments for splice matrices
  resume: false              # set true to continue after OOM/crash
  memory: 64G
```

Equivalent manual command:

```bash
isoquant \
  --reference GRCh38.primary_assembly.genome.fa \
  --genedb gencode.v44.annotation.gtf \
  --complete_genedb \
  --bam tagged_cells/SAMPLE.cells.bam \
  --data_type nanopore \
  --mode tenX_v3 \
  --barcoded_bam \
  --barcode_tag CB \
  --umi_tag UB \
  --strip_barcode_suffix \
  --analysis quantification \
  --counts_format mtx \
  --large_output none \
  --threads 4 \
  --umi_threads 1 \
  --process_threads 1 \
  --output isoquant/SAMPLE \
  --prefix SAMPLE
```

To resume after interruption:

```bash
# pipeline.yml: isoquant.resume: true
cribbslab sclong make quantify --local -j 1
# or manually:
isoquant --resume --output isoquant/SAMPLE --threads 1
```

## Troubleshooting

- **No samples found:** FASTQs must sit in the project root (not subfolders)
  and match `*.fastq.gz` / `*.fastq` / `*.fq*`.
- **Kit mismatch:** Wrong `tenx_kit` causes poor barcode calling; confirm
  chemistry with your 10x kit documentation.
- **Reference/annotation mismatch:** minimap2, FLAMES, and IsoQuant all
  require the same genome build and compatible GTF.
- **OOM during sort/IsoQuant:** Lower `isoquant.threads`, set
  `isoquant.umi_threads: 1` and `isoquant.process_threads: 1`, use
  `isoquant.analysis: quantification`, and set `isoquant.large_output: none`.
  After a crash, set `isoquant.resume: true` and rerun `make quantify`.
  For FLAMES OOMs on large samples, skip FLAMES and rely on IsoQuant.
- **IsoQuant BrokenProcessPool:** Worker killed by OOM during per-chromosome
  UMI dedup. Resume with `isoquant.resume: true` and `isoquant.threads: 1`.
- **Splice matrices missing after IsoQuant:** `large_output: none` skips
  read assignment files. Set `isoquant.large_output: read_assignments` before
  rerunning IsoQuant if you need spliced/unspliced AnnData matrices.
- **CTAT fusion failures:** The CTAT genome lib annotation version must
  match your pipeline GTF; prebuilt v44 libs may not match Gencode v46.

For pipeline internals and task list, see the module docstring in
[`pipeline_sclong.py`](../pipeline_sclong.py).
